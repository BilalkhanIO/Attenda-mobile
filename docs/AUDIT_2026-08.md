# Attenda Mobile — Audit 2026-08

**Scope:** branch `claude/zealous-sagan-8aa4gb` at c1d579c, diffed against `attenda-api` (same branch) and the design contract in `attenda-api/docs/EXPANSION_RESEARCH.md`.
**Method:** every screen under `lib/screens/`, every `ApiService` method (77), the router table, both presence services, the widget-test tree, and the API's full route list (`src/app.ts` MOUNTS + per-router endpoints).

---

## Executive summary — top 10 actionable items

1. **Managers cannot approve leave on mobile.** `ApiService.approveLeave / rejectLeave / getTeamLeave` exist (`lib/services/api_service.dart:307-318`) but no screen calls them — the Approvals hub (`lib/screens/approvals/approvals_screen.dart`) only has Corrections / Expenses / Late Arrivals tabs. Leave approval is the highest-frequency, most phone-shaped manager action in the product (API: `PUT /leave/requests/:id/approve|reject`, `GET /leave/requests/team`). Add a Leave tab to the hub.

2. **FCM presence challenge is unwired — the top reliability gap in the check-in pipeline.** `firebase_messaging` and `flutter_local_notifications` are in `pubspec.yaml` but never imported; `PUT /users/me/device-token` has no ApiService method; the server half is fully built (`attenda-api/src/services/pushChallenge.ts` — high-priority FCM data message that cancels a Doze-induced auto-checkout). Until wired, users still get false auto-checkouts when Android kills the 4-minute foreground cycle.

3. **Approvals hub misses the other pending manager actions the API exposes:** overtime requests (`PUT /overtime/requests/:id/approve|reject` — employees can *submit* OT from mobile but managers can't act on it), remote-session approve/reject (`PUT /attendance/remote/sessions/:id/approve|reject` — the mobile *shows* "Pending manager approval" to the employee), shift-swap approve/reject (`PUT /shifts/swaps/:id/*`), and late-notice acknowledgement (`PUT /attendance/late-notice/:id/acknowledge`). All are queue-shaped, phone-perfect actions.

4. **Notifications don't deep-link and arrive only by polling.** Tapping a tile just marks it read (`lib/screens/notifications/notifications_screen.dart:229`); a `leave_approved` or `kudos_received` notification should navigate to its screen. The home badge polls every 30 s while the API has SSE at `GET /notifications/stream`. The type→emoji map (`:21-37`) is also stale — no entries for `expense_*`, `kudos_received`, `document_added/expiring`, `onboarding_*`, announcements.

5. **2FA enrolment says "Scan the QR code" but never shows one.** `POST /auth/2fa/setup` returns `{secret, uri, qr_code}` (`attenda-api/src/routes/auth.ts:416`); `security_screen.dart:248-257` renders only the manual secret. `qr_flutter` is already a dependency — render the `uri`. Ten-line fix to a confusing security flow.

6. **Theme system is half-applied.** `ThemeController` supports palette + density (no dark mode), but seven pickers force `Theme(data: AppTheme.light, ...)` (home_screen ×2, correction_sheet, expense_claim_sheet, edit_profile, request_leave, break_banners), and dozens of widgets use `const AppColors.primary` (emerald) instead of `Theme.of(context).colorScheme.primary` — e.g. leave ring (`leave_screen.dart:297`), attendance hours chip / PAID badge / break icon (`attendance_screen.dart:410-415, 652-672`), QR scan overlay (`qr_scanner_screen.dart:344-382`), so choosing Cyber/Sunset/Slate produces a two-accent UI, violating the single-accent contract.

7. **Dead weight: ~10 unused packages and 7 unused ApiService methods.** Unused deps: `http`, `uuid`, `equatable`, `flutter_svg`, `cached_network_image`, `qr_flutter`, `firebase_messaging`, `flutter_local_notifications`, `open_filex`, `path_provider` (zero imports in `lib/`). Unused methods: `approveLeave`, `rejectLeave`, `getTeamLeave` (item 1), `getMyLateNotices`, `getTodayAttendance`, `getShiftAssignmentDetail`, `updateProfile` (duplicate of `updateMe`). CLAUDE.md also claims `flutter_riverpod` is in pubspec — it isn't (stale doc).

8. **Older screens fail silently; newer ones don't.** Home, Attendance, Leave, Schedule all `catch (_)` their loads with no error state or retry (`attendance_screen.dart:112`, `leave_screen.dart:37`, `schedule_screen.dart:37`, `home_screen.dart:308`), while every Tier-B screen (Expenses/Documents/Announcements/Onboarding/Kudos/Approvals) has the standard error + Retry pattern. One consistency pass closes it.

9. **Receipt/avatar/document upload dead ends.** `submitExpense` accepts `receiptUrl` but the claim sheet has no photo attach (blocked on a receipt presign route — `POST /documents/upload-url` exists and could be generalised); Documents screen is download-only although the API has the presign→register flow; the profile header renders a camera badge over the avatar (`profile_screen.dart:239-248`) that does nothing.

10. **Hardcoded values that should come from the API/platform:** payslip amounts hardcode `$` (`payslips_screen.dart:128`) while expenses format org currency correctly; the foreground notification says "Reconnect within **10 minutes**" (`foreground_service.dart:172`) although the grace window is org-configurable and defaults to 20 min in `wifi_service.dart:72`; home falls back to a 09:00–17:30 shift (`home_screen.dart:1834,1847`); settings shows a literal "Version 1.0.0 (Build 1)" (`settings_screen.dart:81`) instead of `package_info`.

## 1. API surface with no mobile UI

API routers: `auth, users, attendance(+corrections), leave, shifts, payroll, expenses, documents, onboarding, kudos, performance/analytics/org/reports (misc.ts), org-rbac, org-webhooks, overtime, notifications, holidays, departments, admin*, public, webhooks`.

Ranked by phone relevance:

**High — should exist on mobile**
- **Leave approvals (managers)** — see Exec #1. Also `GET /leave/requests/team` for a team view; methods already written.
- **Overtime approvals (managers)** — `GET /overtime/requests`, `PUT .../approve|reject`. Mobile submits OT (home + attendance detail) but the approver must open the web.
- **Remote-session approvals (managers)** — `PUT /attendance/remote/sessions/:id/approve|reject`, `GET /attendance/remote/sessions`. The employee-side card literally says "Pending manager approval".
- **Swap approvals (managers)** — `GET /shifts/swaps`, `PUT /shifts/swaps/:id/approve|reject`. Employees can request swaps on mobile; nobody can approve them there.
- **Late-notice acknowledgement (managers)** — `GET /attendance/late-notices`, `PUT /attendance/late-notice/:id/acknowledge`. The Late Arrivals tab is a read-only summary; the actionable queue is missing.
- **Device token registration** — `PUT /users/me/device-token` (Exec #2).

**Medium**
- **Leave team calendar** — `GET /leave/calendar` unused; the home Who's-out card covers *today* only. A week-ahead "who's out" view is a natural phone glance.
- **Notifications SSE** — `GET /notifications/stream` unused (mobile polls).
- **2FA QR (uri/qr_code fields)** — returned but dropped (Exec #5).
- **Document upload** — `POST /documents/upload-url` + `POST /documents` (self-service upload of an ID/visa photo is a classic phone job).
- **Announcement receipts for senders** — `GET /performance/announcements/:id/receipts`; managers who send announcements can't see reach. Low-medium.

**Correctly absent (do not add):** payroll generation/adjust/recall, org settings/office-IPs/QR management, RBAC, webhooks, departments CRUD, admin/platform routers, analytics dashboards, onboarding template CRUD, reports. These are console workflows.

**API-side gap worth flagging upstream:** `early_departure` is faked as a late notice with a `[Early Departure]` reason prefix (`api_service.dart:197-204`) — the dedicated endpoint still doesn't exist.

## 2. Incomplete flows

- **Silent load failures** on Home/Attendance/Leave/Schedule (Exec #8). On the home screen a total API failure shows cached data with no "stale / offline" hint apart from the connectivity banner.
- **Profile avatar camera badge is decorative** — no upload flow anywhere (Exec #9).
- **Home quick action "My Payslips" goes to `/profile`, not `/profile/payslips`** (`home_screen.dart:1880`) — user lands on the profile page and must tap again.
- **`/home/remote/detail` renders inside the shell** (no `parentNavigatorKey: _rootKey`, `router.dart:70-75`) while every other detail overlay is full-screen — bottom-nav stays visible, inconsistent.
- **Attendance history fetches 186 days in one request** (`attendance_screen.dart:84`) and filters client-side; no month-by-month fetch. Kudos feed silently caps at 100 (server paginates via page/limit; screen never pages). Approvals queues (corrections/expenses) are unpaginated. Notifications paginates correctly.
- **Notification tiles don't navigate** (Exec #4).
- **Pending swap "received" rows have no action** (`schedule_screen.dart:246-259`) — target user sees "Swap request received" but can't accept/decline (API routes swaps to manager approval, so at minimum the copy should say so; if targets may respond, the action is missing).
- **Expense reviewer flow on mobile stops at approve/reject** — reimbursement is web/payroll-side (correct), but the approved-state card gives the manager no hint of that next step.
- **Correction sheet, expense sheet, give-kudos sheet** are complete (validation, loading, error surfaced) — the newer flows are in good shape.
- **Stale-data-after-mutation is generally handled** (screens reload after sheets), one gap: approving/rejecting in the hub reloads only the affected tab — fine — but home does not refresh its notification badge after actions elsewhere until the 30 s poll.

## 3. Design-contract violations (minimal light contract)

- **Forced `AppTheme.light` in 7 picker builders** — breaks the palette override today and blocks dark mode (Exec #6 list).
- **`const AppColors.primary` bypassing the ThemeController accent** in leave ring, attendance chips, QR overlay, `_RecordTile` hours chip, break-history rows, `remote_detail` etc. Single-accent contract holds only for the default Emerald palette.
- **Off-scale font sizes** (contract: 11/13/15/18/24): `fontSize: 9` (leave HALF-DAY chip :187, schedule TODAY chip :191, attendance PAID chip :672), `10` (attendance :365,438), `12` (six files), `14/16/20/22/28` (security :257, give_kudos :214, kudos emoji :268, qr_scanner :272,288).
- **Non-token colors:** `Color(0xFFF15153)` shift-color fallback (`home_screen.dart:1895`); `Colors.white` as a "neutral tint" sentinel (`home_screen.dart:1599` → special-cased in `GlassCard:38` — fragile); attenda_logo brand hexes (acceptable as brand art).
- **Glass-era naming retained**: `GlassCard`, `GlassBadge`, `glassDetailRow`, `_glassDetailRow` wrapper (attendance_screen:706 — pointless indirection), `_AuroraNavDock` (shell.dart:46). Behaviour is flat/minimal (blur removed, `blurSigma` is a no-op param) but the vocabulary contradicts the contract and invites regressions.
- **Emoji in UI copy** (`'Checked out ✅'`, `'Working Remotely 🏠'`, `'Break started ☕'`, `'🏠 Remote work request submitted!'`, sentiment/nudge emoji in remote_detail) — the web contract's minimal tone has no emoji; at minimum make it consistent.
- **One-off inline chip/badge builds** repeated across screens instead of `StatusBadge`/`GlassBadge` variants: leave status chip (leave_screen:192-198), swap status chip (schedule:251-258), remote status chip (remote_detail:227-243), correction chip (attendance:425-441), expense chip (own class, fine). One `AppStatusChip(label, fg, bg)` would delete ~5 copies.
- **Leave balance progress bar width is `MediaQuery.width * 0.7 * pct`** (`leave_screen.dart:362`) — a guess, not a layout; use `FractionallySizedBox`/`LayoutBuilder`.

## 4. Presence pipeline reliability/UX

Strong foundation: Reliability screen (`settings/reliability_screen.dart`) live-checks service/battery/notification/location/heartbeat with fix actions and an OEM (Samsung/Xiaomi/…) hint card; VPN and no-networks banners on home; disconnect countdown card; server-driven grace window.

Gaps:
- **FCM presence challenge unwired** (Exec #2) — the one server feature designed to prevent wrongful auto-checkout can't reach the device.
- **Offline queue is invisible.** Events queue in Hive and replay silently; neither home nor the Reliability screen shows "N events pending sync" or last-sync time. A row in Reliability (box length + oldest timestamp) would make offline behaviour trustworthy.
- **Hardcoded "10 minutes" in the background notification** vs org-configurable grace (Exec #10). Also `wifi_service.graceWindow` starts at 20 min and only corrects after the first heartbeat ack — the first disconnect after app start can show a wrong countdown. CLAUDE.md still documents "10-minute grace" and a "2 h" queue discard while the code uses 12 h (`wifi_service.dart:419`).
- **Permission prompts all fire in `main()` before first frame** (`wifi_service.init()` — location, notifications, battery exemption) with no rationale UI; on first launch users see three system dialogs before the login screen. Move to a post-login primer or the Reliability screen.
- **`checkAndReport()` 30 s throttle also throttles pull-to-refresh** (`wifi_service.dart:229-235`) — the one place a user explicitly asks for a re-check can be a silent no-op.
- **`syncOfflineQueue` replays `checkIn(type:'manual')`** for queued check-ins with no user-visible outcome (success/failure never surfaced).
- iOS: foreground-task options are Android-centric; if iOS is out of scope, state it (README/CLAUDE.md) — the code paths would quietly do nothing.

## 5. Code quality

- **`home_screen.dart` is 1,900 lines** and mixes state machine, banner priority logic, dialogs and formatting. The extracted `widgets/` help, but `_showAttendanceRequestDialog` (312 lines) and the break-banner selector belong in their own files; `_asDouble/_asInt/_parseLocal/_totalBreakMinutes` are duplicated in `attendance_screen.dart` — move to a shared `utils/parse.dart`.
- **`ApiService`: 77 methods, 613 lines** — still readable but heading to god-object; the section comments are ready-made seams for `api/attendance_api.dart` etc. Duplicates: `updateProfile` vs `updateMe`; `refreshToken` duplicates the interceptor's refresh logic (and the interceptor does not de-duplicate concurrent 401 refreshes — token-rotation family revocation risk if two requests 401 simultaneously; also `_storage.deleteAll()` on refresh failure logs the user out silently with no AuthProvider notification, leaving UI signed-in until restart).
- **setState-after-await without `mounted`**: `notifications_screen.dart` `_markRead`/`_markAllRead`/`_delete` (:72-105); `attendance _showDetail`'s `Navigator.pop(context)` inside `StatelessWidget` callbacks is fine, but `payslips_screen.dart` download `GestureDetector` uses `context.mounted` correctly — the notifications screen is the one real risk.
- **Dead code / dead deps**: Exec #7 list; also `getMyLateNotices` superseded by `getLeaveAndNoticeCheck`; `UserAvatar` uses raw `NetworkImage` (no caching, no error builder — broken avatar URLs throw render errors) while `cached_network_image` sits unused in pubspec.
- **Router**: no dead routes; all imports used. Inconsistency: `/home/remote/detail` missing root navigator key (see §2). Deep-link paths for new features exist only under `/profile/*`.
- **CLAUDE.md staleness**: claims riverpod dep, 10-min grace, 2 h queue discard, `localhost:5000` default API URL (code default is the Railway production URL — a debug-vs-prod footgun worth calling out on its own: a dev build with no `--dart-define` talks to production).

## 6. Test coverage holes

Present (~100 tests): api_failure mapping; widget tests for correction sheet, approvals cards, expense sheet/cards, kudos card + sheet, announcement card, onboarding card, document card, home banners/break banners/status card/quick actions/shift card/ring/disconnect card/break control.

Missing — highest value first:
1. **`WifiAttendanceService` / offline queue**: queue replay, 12 h discard, 4xx drop, grace-deadline math, `_onTaskData` transitions. Pure-Dart logic, easily unit-tested, zero coverage.
2. **Auth + router redirects**: login → 2FA partial-token path, `/2fa` without extra → `/login`, feature-gate redirects (`/leave` without `leave_management`), token-refresh-on-boot.
3. **ApiService interceptor**: 401 refresh + retry + rotation persistence (mock Dio adapter).
4. **Screen-level flows for the older tabs**: leave list/cancel, schedule swap sheet (403 fallback branch), notifications pagination + mark-all/dismiss, attendance month filtering + summary counts.
5. **Approvals hub tab gating** (expenses tab visibility by capability) — the cards are tested, the gating logic isn't.
6. **Security screen 2FA state machine** (setup → verify → enabled; disable path).

## 7. Missing features worth adding (ranked, phone-first)

1. **Push notifications + deep links** (FCM registration, tap → screen; unlocks presence challenge, approvals, kudos). Foundation for everything else here.
2. **Manager approvals completion** — leave/overtime/remote/swaps/late-notice tabs (or a unified "Inbox") in the existing hub; badge count on the Settings entry.
3. **Biometric app lock** (`local_auth`) — attendance, payslips and documents are sensitive; tokens already in secure storage; low effort, high perceived quality.
4. **Dark mode** — `ThemeController` already rebuilds `ThemeData`; the blockers are the ~7 forced-light pickers, const `AppColors` text styles (need theme-resolved styles), and `StatusColors` needing a dark variant. Estimate: mechanical 1–2 day pass once tokens are parameterised, big daily-use win for a check-in app used outdoors/at night.
5. **Home-screen widget / quick-settings tile** (Android `HomeWidget`/tile: current status + elapsed timer + check-out action) — the app's core loop is a glance.
6. **Offline mode messaging** — global "offline, N actions queued" chip fed by the Hive queue + connectivity (see §4), plus queue visibility in Reliability.
7. **Who's-out week view / team leave calendar** — `GET /leave/calendar` + existing who's-out endpoint; helps everyone plan, not just managers.
8. **Localization readiness** — all strings are hardcoded English; `intl` is already a dep. Introduce `flutter_localizations` + ARB extraction before the string count doubles again (the org base includes non-English locales; date formats are already locale-sensitive via `DateFormat`).
